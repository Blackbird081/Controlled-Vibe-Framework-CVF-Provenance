## Read-Only Value And Cost Method

Score each dimension from 0 through 5 and cite at least one repo-local source
for every non-zero score. Apply the listed weight. Uncited scores are zero.

### Value Score

| Dimension | Weight | Required evidence |
|---|---:|---|
| current workflow blocker removed | 3 | named non-test workflow and concrete missing outcome |
| reusable by two or more current consumers | 2 | current caller/import/config evidence for each consumer |
| contract-to-runtime system-chain gap closed | 3 | exact missing edge and proposed proof class |
| security or authority ambiguity reduced | 3 | current source behavior and bounded improvement |
| operator-visible evidence or learning improved | 1 | current operator surface or accepted GAP destination |

Maximum weighted value: 60.

### Cost Score

| Dimension | Weight | Required evidence |
|---|---:|---|
| new runtime owners and changed surfaces | 3 | exact path/owner estimate |
| attack surface and authorization complexity | 3 | ingress, identity, policy, redaction, abuse cases |
| test, observability, and operational burden | 2 | required suites, receipts, monitoring, failure handling |
| authoritative data and receipt lifecycle complexity | 3 | owner, freshness, persistence, retention, reconciliation |
| maintenance, duplication, and migration burden | 1 | overlap with existing route/catalog/consumer owners |

Maximum weighted cost: 60.

### Stable-Margin Rule

`PROCEED_BOUNDED_SYSTEM_CHAIN` requires weighted value to be at least 12 points
higher than weighted cost. Rerun sensitivity by reducing every value dimension
with medium/low confidence by one and increasing every cost dimension with
medium/low confidence by one. If the margin falls below 12, use
`STOP_LOW_VALUE`. This deliberately treats marginal value as insufficient.

Failure of gates 1 or 8 requires `STOP_LOW_VALUE`. Failure of gates 2 through
7 requires `BLOCKED_MISSING_PREREQUISITE` unless the same evidence also proves
