## Scope / Methodology

Implement a pure TypeScript evaluator accepting `unknown`. Its explicit input
contains a current `ControlledAcquisitionPlan`, expected workspace ID,
expected actor ID, optional expected work-order ID, caller-provided `now`, and
rich approval evidence with exact schema version, identity, plan binding,
workspace/work-order binding, decision, actor, issue/expiry times, nonce, and
mutation envelope.

Output is evidence only: `VALIDATED_EVIDENCE` or `REJECTED`, normalized IDs and
digest only on success, explicit issues, `replayCheckRequired: true`, and
literal false execution/acquisition/mutation/task/network authority.

## Functional Requirements

1. Accept `unknown`; reject non-plain objects, proxies/accessors, sparse or
   oversized arrays, unknown keys, hostile nested values, symbols, and control
   characters without invoking traps/getters.
2. Require the exact current T3 plan schema and recompute its deterministic
   digest using the current owner; reject expired or issue-bearing plan input.
3. Require approval evidence schema `cvf.capabilityBootstrapApprovalEvidence.v1`,
   unique bounded IDs, lowercase SHA-256 digest, decision `APPROVE`, valid UTC
   issue/expiry times, and expiry no later than plan expiry.
4. Bind exact plan ID/digest, expected workspace, expected actor, and exact
   optional work-order expectation. Null/absent semantics must be explicit.
5. Normalize current T3 mutation kinds into bounded approval-envelope classes
   and require exact set equality for kind+target; reject missing, extra,
   duplicate, ambiguous, irreversible-without-explicit-marker, or secret-like
   envelope entries.
6. Validate a bounded replay nonce but never claim uniqueness or consume it;
   every success must expose `replayCheckRequired: true`.
7. Never echo notes, raw source URI, operation arguments, secrets, nonce, actor
   detail beyond validated actor ID, or mutation descriptions.
8. Keep `approvalIssued`, `executionAuthorized`, `acquisitionAuthorized`,
   `mutationAuthorized`, `taskAuthorityGranted`, and `networkAuthorized`
   literal `false` on every return path.
9. Stable issue ordering, stable normalized output, no input mutation, and
   identical output for identical explicit input.
10. Export through both existing Guard Contract barrels without altering T3.
