### Decision Output And Algorithm

For a valid declared record emit additive receipt fields only:

- `valueDisposition`: exactly one of the four accepted tokens;
- `valueDispositionAuthoritative`: always `false` in TV2;
- `valueDispositionReasonCodes`: stable sorted non-empty codes.

Omitted records emit none of these fields, preserving old receipt equality.
Rejected manifests retain full P3 fallback, selective execution false, and
full legacy disposition.

Decision precedence:

1. malformed/missing declared fields or unverified authority -> park;
2. proved dependent/duplicate root cause without new evidence -> stop;
3. cap exhausted -> consolidate a source-backed P0/P1 with a new-roadmap code,
   otherwise stop; never execute a fourth tranche;
4. P0/P1 without observed/historical finding proof -> park;
5. source-backed P0/P1 with independent root cause and observed/historical
   marginal value -> continue; otherwise consolidate one bounded repair;
6. P2/P3/NONE continues only for independent root cause plus observed or
   historical-bounded marginal value; projected/unknown value parks;
7. stale/expired record parks; an override never overwrites the computed token
   and cannot become authoritative without a valid governed reference and
   independent reviewer evidence.

Risk-profile computation happens first and is immutable. Value output never
changes profile, bundles, escalation triggers, selective execution, or legacy
gate disposition.
