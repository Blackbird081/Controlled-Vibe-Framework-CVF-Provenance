## Implementation Contract

Extend the existing HRLTP JSON contract with one closed
`operationalRoleCapabilityConsistency` object. The standard and checker must
define exact keys, closed enum values and deterministic relation rules for:

- actor identifiers and actor class;
- resource identifiers and resource class;
- controlled operation vocabulary;
- per-actor/resource allowed and forbidden operation sets;
- required actions and observations, including execution actor and separate
  evidence owner where applicable;
- recovery residue identity, cleanup actor, required capability and
  unknown-artifact disposition;
- evidence mode and maximum claim ceiling.

Required invariants:

1. an applicable relation contains at least one actor, resource and required
   action; actor, resource and action IDs are non-empty and unique;
2. each actor/resource pair has exactly one capability row and its allowed and
   forbidden sets are duplicate-free and disjoint;
3. every required action references known actor, resource and operation;
4. the operation occurs in that actor/resource allowed set and not its
   forbidden set;
5. each evidence owner is a known actor whose capability permits the required
   observation on that resource;
6. operations are compatible with resource classes; parent-directory
   child-deletion cannot be attached to or substituted by an individual-file
   deletion operation;
7. recovery fields are complete together, cleanup capability is available to
   the cleanup actor, and unknown residue is preserved and blocks authority;
8. evidence declares obligation, current evidence state and claim ceiling. A
   normative design may carry future actual-token proof as `PENDING` only at a
   contract-only ceiling; pending or hermetic evidence cannot support an
   operational-ready or real-principal claim;
9. normative design/amendment packets are applicable even when execution is
   deferred; pure examples and checker-only fixtures remain excluded;
10. unchanged historical work orders remain outside forward-only adoption;
11. diagnostics identify the failed relation without exposing secrets;
12. static PASS never claims runtime truth.

Do not prescribe implementation algorithms, file decomposition beyond the
exact owners, Windows API choice, worker reasoning or model selection.
