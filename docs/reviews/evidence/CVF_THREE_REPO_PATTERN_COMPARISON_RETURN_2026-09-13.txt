## 2. Executive revision

The September 11 domain choice still holds: the pilot is useful because Agentgateway and QM share governance principles while applying them in materially different runtime surfaces, and DeepSeek Harness remains a distinct application control around event-sourced execution state.

However, two earlier formulations were too broad:

1. `PILOT-MECH-002` should not be read as “one verified principal/scope is universally propagated everywhere.” Agentgateway authentication is configuration-sensitive, while QM's own security posture documents incomplete or bypassing paths.
2. `PILOT-MECH-003` should not be read as “all policy composition is globally fail-closed.” The useful common principle is narrower: authority-bearing policy composition should not silently widen authority, but coverage and enforcement differ by path, configuration, and source.

The strongest unchanged distinction is `PILOT-MECH-004`: DeepSeek's canonical append-only event state with derived model-visible history remains materially different from generic audit/telemetry.

## 4. Agentgateway regex / webhook / masking distinction

The relay explicitly asks that Agentgateway content-guard behavior not be turned into a claim about what CVF “needs.”

The useful distinction is:

| Surface | What it represents | What it does **not** prove |
|---|---|---|
| Response masking | A transformation/enforcement action on returned content when a guardrail produces a masking/anonymization outcome | That masking is the correct CVF response for every unsafe/governance result; masking can hide evidence if applied at the wrong owner boundary |
| Guardrail audit / metrics | Evidence that a guardrail ran and which coarse action occurred; current Agentgateway public discussions describe `allow/mask/reject` counters and note gaps in richer decision-trace detail | That logging itself prevents an unsafe action or creates authorization |
| Webhook guardrail | An external/custom evaluation mechanism invoked as a guardrail backend | That the webhook is an authority root, that it is fail-closed in every configuration, or that CVF should replace existing DLP/SAF policy owners with it |
| Regex guardrail | Deterministic pattern-based content detection/transformation | Semantic safety, authorization, or complete DLP coverage |

The Local-attested context already classifies `AGW-UC-02` as `DEFER_WITH_TRIGGER`: response masking is a source capability, while an authorized CVF consumer policy is still missing and existing DLP/SAF responsibilities must be considered. This pass does **not** reopen that decision.

Current public Agentgateway documentation corroborates that guardrails include regex and custom webhooks, and current public guardrail discussions distinguish blocking/masking from observability. Exact pinned content-guard source bytes at `3d5f59...` were not independently fetched in this pass, so no new pin-specific content-guard finding is asserted.

**Local question:** If AGW response masking is ever reconsidered, which existing DLP/SAF owner is allowed to request masking, what evidence remains unmasked for review/audit, and which unsafe/governance decisions must remain explicit reject/hold rather than be transformed into apparently “safe” output?

## 6. Advisory contribution versus Local runtime absorption

The external domain-funnel step is useful when it does three things:

1. compresses repeated architectural language into a small number of mechanism groups;
2. preserves application-specific residuals instead of discarding a repo as “duplicate”;
3. returns precise Local questions where public evidence cannot decide equivalence.

It is **not** a substitute for Local runtime-value recovery. The QM correction is the clearest example: a high-level pattern can be directionally right while source-native security limitations materially change the strength and scope of the claim.

Therefore this pass supports the **method** of bounded cross-repository pattern triage, but it does not establish that every retained pattern should be absorbed or that broader rollout is pre-approved.
