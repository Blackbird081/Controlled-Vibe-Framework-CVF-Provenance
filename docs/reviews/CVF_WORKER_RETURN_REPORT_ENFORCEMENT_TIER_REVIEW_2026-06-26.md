## Purpose

Classify the worker-return/reporting checks that were creating repeated
agent repair loops, then authorize a bounded guard-helper adjustment that
keeps authority and evidence controls hard while lowering non-critical
format pressure.

## Target / Source

Target owner: Codex reviewer/maintainer for a bounded governance-helper
maintenance batch.

Source trigger: operator report on 2026-06-26 that strict worker-return
report formatting created repeated repair loops and token/time pressure.

## Scope / Methodology

Scope includes only worker-return/reporting checker friction and scaffold
support. Method: read the relevant local checkers, classify controls by
whether they protect authority/evidence or only report wording, then patch
the narrow over-broad triggers with focused tests.

## Findings / Position

Position: keep hard gates for authority, scope, source evidence, receipt,
and protected paths. Reduce hard-fail behavior only where the check is a
format/prose proxy that does not itself protect code quality, closure
truth, or orchestrator decision quality.

## Risk / Corrective Action

Risk: loosening a report checker can hide a real evidence gap if the
trigger was also guarding a source-fact claim.

Corrective action: keep strong equivalence phrases under hard checking,
reject corpus N/A when a corpus-completeness claim is present, keep
provider-memory and reusable-learning escape checks hard, and add focused
tests for each relaxed path.

## Enforcement Tier Decision

Hard-fail remains appropriate for:

- authority artifacts and provider-memory boundary;
- protected path authorization;
- source verification and required first-read evidence;
- executed gate evidence and receipt presence;
- actual changed-set path lists;
- public/provenance boundary claims;
- runtime/provider/live-proof claims.

Hard-fail is reduced for:

- plain status wording that says a path is unchanged;
- the required worker-return heading `## Findings / Position` when it is
  not an actual defect-learning section;
- non-corpus worker returns that include a compact
  `NOT_APPLICABLE_WITH_REASON` corpus verdict with a reason.

Scaffold support is added for worker-return packets so agents can start
from machine-shaped sections instead of discovering literal-format
requirements after drafting a long report.
