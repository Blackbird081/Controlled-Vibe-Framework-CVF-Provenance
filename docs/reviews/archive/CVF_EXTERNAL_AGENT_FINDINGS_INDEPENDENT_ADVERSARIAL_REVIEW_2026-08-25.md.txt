## Findings

### F1 - A live durable-memory HTTP write path was missed

Document conclusion:

> The durable store is an exported, constructible API surface. No live write
> path was traced.

This is wrong.

Evidence:

- The HTTP body declares `provenanceScore?: number` at
  `EXTENSIONS/CVF_v1.6_AGENT_PLATFORM/cvf-web/src/app/api/memory/write/route.ts:24`.
- Validation permits omission and preserves it as `undefined` at the same file
  `:100-115,125-134`.
- The route requires a session or signed service token at `:151-178`.
- The authenticated caller supplies `actorAuthorized` and `policyDecision`,
  which are used as the policy gate at `:202-208`.
- When the store path is configured, the route constructs the file-backed store
  and calls `write` at `:211-233`.
- The store converts the omitted value to `1` and persists it at
  `EXTENSIONS/CVF_LEARNING_PLANE_FOUNDATION/src/durable-memory-store.ts:249,287`.

Corrected claim: the defect is reachable through an authenticated HTTP write
route when the durable-store path is configured. Deployment, external exposure,
and exploitation remain unproven.

### F2 - A second fail-open provenance default reaches model context

Both documents missed:

- AIF memory items accept optional provenance at
  `EXTENSIONS/CVF_v1.6_AGENT_PLATFORM/cvf-web/src/lib/aif-memory-reinjection.ts:3-18`.
- Missing provenance is treated as `1` at `:99`.
- Eligible summaries are placed into a prompt block at `:103-136`.
- The block is converted into a governed reinjection system prompt at `:149-150`.
- The execute route evaluates the request and attaches the block to the system
  prompt at
  `EXTENSIONS/CVF_v1.6_AGENT_PLATFORM/cvf-web/src/app/api/execute/route.ts:744-753`.
- The enriched prompt is sent to the provider at `:784-790` and reused on
  retry at `:840-844`.

`rawMemoryReleased=false` on the separate readout route does not bound this
path. This is summary-only model context, not raw-memory release, but it can
still influence provider output.

### F3 - GC-022 status and owner resolution are incorrect

The verification report says only archived GC-022 artifacts exist, and the
proposal repeats that premise. Active authority contradicts it:

- `governance/toolkit/05_OPERATION/CVF_MEMORY_GOVERNANCE_GUARD.md:3-5`
  identifies GC-022 as an active durable-memory classification contract.
- `docs/reference/CVF_MEMORY_RECORD_CLASSIFICATION.md:5,63-66` is the canonical
  memory-record classification reference.
- `docs/reference/CVF_GOVERNANCE_CONTROL_MATRIX.md:7,59` is the canonical
  ownership map and registers the current GC-022 guard, reference, and checker.

GC-022 owns record-classification semantics; it does not necessarily own
retrieval admission, runtime write authorization, or TruthReference semantics.
The correct disposition is distributed-owner reconciliation, not replacement
of GC-022 by the EVEROS-T2 matrix.

### F7 - `matchesQuery` is not proven to be a P1 defect

`matchesQuery` performs lexical relevance filtering at
`EXTENSIONS/CVF_LEARNING_PLANE_FOUNDATION/src/memory-retrieval-policy.ts:98-104`.
That mechanism can be shaped by caller-provided or record-carried text, but the
cited code does not prove malicious admission, privilege gain, downstream
action, or exploitability. Calling both fields attacker-controlled is stronger
than the evidence.

Recommended disposition: P2 advisory or unproven threat-model gap unless a
source/admission path demonstrates hostile records crossing an authority
boundary.

### F8 - `auditTrust` impact is narrower than P1 evidence currently proves

The HTTP route accepts caller-supplied `auditTrust` with type-only validation at
`EXTENSIONS/CVF_v1.6_AGENT_PLATFORM/cvf-web/src/app/api/memory/readout/route.ts:82-100`,
and ranking uses it at
`EXTENSIONS/CVF_LEARNING_PLANE_FOUNDATION/src/memory-retrieval-policy.ts:244-256`.

However, the readout route sanitizes candidate content and explicitly returns
`rawMemoryReleased:false` and `canReinject:false` at
`EXTENSIONS/CVF_v1.6_AGENT_PLATFORM/cvf-web/src/app/api/memory/readout/route.ts:193-204`.
No downstream action path from this route was traced.

Recommended disposition: range validation is sound, but security impact remains
P2 or unproven until the selected readout is shown to drive an authorization,
provider prompt, or execution decision.
