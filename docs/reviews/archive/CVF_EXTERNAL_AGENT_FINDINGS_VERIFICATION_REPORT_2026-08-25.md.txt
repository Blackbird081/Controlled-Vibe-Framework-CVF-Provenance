### 6.3 V8 — new finding not reported by the external agent

Verified at lines 98-104:

```ts
function matchesQuery(candidate: MemoryRetrievalCandidate, query: string): boolean {
  const normalized = query.trim().toLowerCase();
  if (normalized.length === 0) {
    return true;
  }
  return `${candidate.summary} ${candidate.content ?? ""}`.toLowerCase().includes(normalized);
}
```

Relevance is decided by a **substring match against attacker-controllable
stored text** (`summary` + `content`). A memory record crafted to contain the
expected query string is therefore maximally "relevant" by construction.

Combined with §6.2, the composed retrieval behavior is: *content the record
itself carries* decides relevance, and *a confidence number the record itself
carries* decides rank. Neither input is independently grounded.

This is precisely the "query-shaped false memory" fixture the external agent
listed as a required test case in its §18 — but the agent did not report that
the current implementation already exhibits the enabling mechanism.

**Verdict: CONFIRMED_NEW (P1).** Recommend this be added to any repair or
evaluation packet.

Explicit non-claim: no exploit was executed, no live retrieval path was
invoked, and `rawMemoryReleased = false` still bounds downstream impact.

### 6.4 V7 addendum — `auditTrust` crosses a package boundary as caller-supplied input

Added after a delayed search completed; not present in the first issue of this
report.

`auditTrust` is not confined to the Learning Plane package. It appears in the
web platform HTTP surface:

`EXTENSIONS/CVF_v1.6_AGENT_PLATFORM/cvf-web/src/app/api/memory/readout/route.ts`

| Line | Verified fact |
| --- | --- |
| 19-28 | `candidates[]` is part of the **HTTP request body** type; each candidate carries `auditTrust: number` |
| 25 | `auditTrust: number;` declared as a caller-provided field |
| 90 | validation is `typeof cand.auditTrust !== 'number'` — **type check only**, no range or provenance check |
| 99 | value is passed through unchanged into the candidate object |

Composed consequence: for this route, the trust scalar used for ranking is
**supplied by the caller in the request body**, not derived by the server from
graph/KGR confidence as in `memory-retrieval-policy.ts:77,92`. A caller may
submit `auditTrust: 1` for any candidate, and only its numeric type is checked.

This is the same defect class the RFR-R7A reviewer rejected as
**self-attestation** (R7A-F2): a caller declaring its own authority evidence.

### 6.5 Mitigating control — the route is authenticated

Verified at lines 135-163 of the same file: the `POST` handler requires either
a valid session cookie (`verifySessionCookie`) or a signed service token
(`verifyServiceTokenRequest` with `x-cvf-service-token`,
`x-cvf-service-signature`, `x-cvf-service-timestamp`), and returns `401`
otherwise.

Therefore this is **not** an unauthenticated public poisoning endpoint. The
correct characterization is narrower:

> An **authenticated** caller can supply an arbitrary in-range trust scalar that
> is used for ranking, with no server-side derivation or bound.

Severity assessment: P1, not P0. Authentication bounds *who* can do this; it
does not restore the epistemic property, because an authenticated caller is
still not an authority on the trustworthiness of the record it submits.

**Verdict: CONFIRMED_NEW.** This materially strengthens the case for narrowing
the scalar's semantics and answers, negatively, the open question of whether
`auditTrust` is package-internal.

Cited-figure reconciliation against the external agent's report:

| Figure as reported by the agent | Source text | Verdict |

| corpus = LongMemEval | LongMemEval | ACCURATE |

| aggressive weighting suppresses legitimate untrusted evidence | "settings strong enough to resist poisoning simultaneously suppress legitimate untrusted evidence" | ACCURATE |
| authors propose bounded occupancy | "proposes bounded occupancy constraints at retrieval" | ACCURATE |

Additional figures present in the source that the agent did **not** cite, and
which strengthen its own argument:

- the screening pipeline achieved **0.832 recall on indirect prompt injection**
  while rejecting **0 of 360** plain poisoned memories — i.e. prompt-injection
  screening and poisoning defense are empirically distinct problems;
- when answer-bearing evidence itself arrived untrusted, accuracy fell to
  **0.0417 with zero evidence recall** — the strongest available evidence for
  the concern raised in §6.2 about trust-scalar suppression of valid evidence.

**Verdict: CONFIRMED.** No figure was fabricated or inflated. The agent's
citation discipline was, if anything, more conservative than the source.
