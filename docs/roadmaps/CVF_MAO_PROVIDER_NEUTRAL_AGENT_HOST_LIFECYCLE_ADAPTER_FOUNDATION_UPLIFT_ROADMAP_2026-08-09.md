## Provider Independence Invariants

1. No provider, model, account, API key, executable, CLI, MCP server, or host
   product name appears in a normative interface field.
2. The port reports capabilities and observed outcomes; it does not infer them
   from provider-specific memory or hidden session state.
3. Provider-native internal helpers remain inside the already-authorized parent
   session boundary and do not create a new external-host claim.
4. T1 must choose capability discovery via an explicit operation, a manifest
   returned at dispatch, or a source-justified attempt-based model. Missing
   cancel, status, identity, or usage capability fails closed or returns an
   explicit unsupported result; it is never silently treated as success.
5. Provider routing, credentials, cost, retry policy, and live diagnostics stay
   with existing owners and require separate authority.

## Agent Sovereignty And Minimal Governance Boundary

Binding invariant: CVF never inspects, constrains, serializes, requests, or
requires disclosure of an agent's private reasoning or chain-of-thought,
internal planning, token stream, provider memory, or provider-native cognitive
workflow. None of those surfaces may be an adapter input, status field, receipt
field, audit requirement, reviewer demand, or acceptance condition.

CVF governance is limited to externally meaningful boundaries:

- admission, authority, scope, and aggregate budget;
- declared capabilities and explicit unsupported capabilities;
- external side effects and tool permissions where applicable;
- coarse lifecycle state and meaningful declared milestones;
- output/result validation and correlated, minimized receipts;
- reviewer admission and commit/public boundaries.

Provider adapters remain opaque behind a declared capability and observed-
outcome contract. A provider may implement its internal workflow however it
chooses inside the admitted envelope. CVF may validate the declared result and
external effects, but cannot infer visibility into, or control over, internal
thought or provider-native descendants.

The host port never injects private-reasoning disclosure metadata, never
requires such metadata, and never scans an opaque admitted task payload for
words such as `thought` or `reasoning`. Enforcement applies only to prohibited
adapter/control schema fields or an explicit control-layer requirement that
private reasoning be disclosed. Ordinary opaque task content remains opaque.

Opacity, provider autonomy, the low-risk fast path, and sparse receipts never
waive authority, admission, scope, aggregate budget, or applicable external-
effect/tool permissions. An external result without correlated launch or
admission evidence cannot become CVF-accepted material. Every external effect
must be pre-authorized within scope and tool permissions; only material effects
need dedicated receipts, while irreversible or high-risk effects retain their
required operator/policy checkpoints.

## Proportional Control, Latency, And Cost Principles

1. Apply controls proportionally to risk; low-risk admitted tasks need a fast
   path and do not require mandatory fan-out or a reviewer for every task.
2. Do not require a synchronous governance round trip at each agent step.
3. Compile and cache immutable authority/scope/budget material once per admitted
   task or material authority revision, rather than repeatedly reconstructing it.
4. Emit correlated minimized receipts only at admission, a material external
   effect, terminal result, or an explicitly authorized meaningful milestone.
5. Heartbeats are sparse, configurable liveness signals only. No per-token,
   per-step, or continuous reasoning receipt is permitted.
6. T1 and T2 must reuse `MaoBudgetAllocation` for existing invocation, token,
   concurrency, revision, and wall-clock ceilings, and justify only the missing
   receipt-count/bytes, polling/wakeup, and control-round-trip measures before
   any BUILD authorization.
7. T3 and later cannot proceed without deterministic evidence that the proposed
   controls remain within the ratified overhead budget and preserve the low-risk
   fast path.

## Proposed Lifecycle Semantics

| Operation | Bounded semantic | Required fail-closed result |
|---|---|---|
| `dispatch` | project `MaoAuthorityEnvelope` and existing launcher/invocation inputs into one bounded task envelope and idempotency key; identity allocation and capability discovery remain T1 decisions; the task body stays opaque | reject missing/stale authority, unsupported capability, duplicate mismatch, ambiguous identity, or a prohibited disclosure field in the adapter/control schema; never content-scan the opaque task body |
| `send` | genuinely novel candidate for one bounded message or clarification to an existing identity; T1/T2 must define per-identity ordering, acknowledgement, restart durability, and either an idempotency key or explicit at-most-once non-durable delivery | reject unknown/closed task, duplicate or reordered message outside the ratified model, oversized payload, or steering cadence above the bound |
| `wait` | possible event-driven composition of existing heartbeat, timeout, orphan, ledger, and read-model owners until a canonical milestone, terminal state, or deadline | return deadline/unsupported/interrupted/stale explicitly; enforce wakeup ceilings; preserve coherence with `status` and the recoverable-hold semantics of `blocked` and `timed_out` |
| `interrupt` | project existing cooperative cancellation; effect idempotency means at most one cancellation effect, while response values may change deterministically from requested to accepted or already-terminal as state advances | return state-accurate requested/accepted/unsupported/already-terminal; never claim control of internal thought or provider-native descendant processes |
| `status` | project the deterministic generated read model through a total mapping from `MaoTaskState`; T1 owns monotonicity, freshness/staleness, and milestone-vocabulary decisions, not a second state lattice | return unknown/unsupported/stale rather than fabricate or regress state; preserve `blocked` and `timed_out` as recoverable non-terminal holds; never expose hidden reasoning, plans, or token streams |
