# CVF VI5-T4/T5 Surface 1 Export Acceptance And Portable Handoff Roadmap

Memory class: ROADMAP_RECORD

docType: roadmap

Date: 2026-05-26

Status: AUTHORIZED_FOR_IMPLEMENTATION

## Purpose

Close the next bounded VI5 step after Surface 1 web export i18n coverage:

- VI5-T4: prepare a real non-coder acceptance gate for the fixed Surface 1
  `app_builder_complete` web export.
- VI5-T5: make the exported English markdown packet more useful for an
  external agent by adding a portable handoff readiness block.

## Authorization / Decision

Decision: proceed with a bounded implementation for Surface 1
`app_builder_complete` English full export only.

This roadmap is authorized because the operator requested completion of
VI5-T4 and VI5-T5, and the previous Surface Fidelity review established that
Surface 1 web export is the correct target for the real non-coder test.

## Scope / Target / Owner Boundary

Target surface:

- Surface 1 web export markdown generated by
  `EXTENSIONS/CVF_v1.6_AGENT_PLATFORM/cvf-web/src/components/SpecExport.tsx`.

Template:

- `app_builder_complete` only.

In scope:

- deterministic renderer changes for English export readability;
- explicit external-agent handoff instructions;
- source-value preservation rules;
- acceptance/readiness checklist for the operator and receiving agent;
- focused tests proving the exported markdown contains the new handoff block
  and does not reintroduce known Vietnamese chrome leakage.

Out of scope:

- provider/API/live governance behavior;
- semantic translation of user-entered Vietnamese values;
- all-template export coverage;
- UI shell redesign;
- external-agent execution result certification;
- cross-agent memory Alpha/Beta/Gamma/Delta decisions.

## Non-Goals

This tranche does not certify external-agent build quality, expand all-template
coverage, redesign the web shell, change provider routing, or implement
cross-agent memory auto-load.

## Work Plan

1. Add a portable handoff readiness section to the bounded English full export.
2. Add focused regression coverage for inclusion, exclusion, and source-value
   preservation.
3. Run deterministic web checks.
4. Update completion and handoff state as `READY_FOR_OPERATOR_ACCEPTANCE`.

## Work Packages

### T4 Acceptance Gate

Deliver:

- acceptance checklist for operator test;
- explicit pass/hold criteria;
- evidence packet showing deterministic test readiness.

### T5 Portable Agent Handoff

Deliver:

- a `Portable Agent Handoff Readiness` section inside English
  `app_builder_complete` export;
- receiving-agent authority and guardrails;
- source-value handling rule;
- external-agent acceptance checklist;
- clarification rule for missing material details.

## Evidence Plan

Required:

- focused unit tests for `generateSpec(app_builder_complete, ..., 'en', 'full')`;
- `npm run check`;
- private handoff/session update after commit.

Optional after implementation:

- operator manual export from web and external-agent evaluation.

Live provider/API proof is not required because this tranche changes
deterministic web export markdown and does not claim provider or governance
route behavior.

## Acceptance Criteria

- English full `app_builder_complete` export includes a portable handoff block.
- Vietnamese user-entered values remain preserved as source evidence.
- The handoff block does not appear in unrelated templates, Vietnamese export,
  or non-full export.
- T4 remains `READY_FOR_OPERATOR_ACCEPTANCE` until the operator performs the
  manual web export and external-agent review.

## Stop Conditions

Stop if:

- the renderer cannot be bounded to `app_builder_complete`;
- tests show user-entered Vietnamese values are being translated or dropped;
- the implementation requires provider, route, receipt, or prompt-runtime
  changes.

## Claim Boundary

This roadmap may claim only bounded Surface 1 English export readiness for
operator/external-agent review. It does not claim that the external agent will
build correctly, that all templates are portable, or that CVF has achieved
hosted production readiness.
