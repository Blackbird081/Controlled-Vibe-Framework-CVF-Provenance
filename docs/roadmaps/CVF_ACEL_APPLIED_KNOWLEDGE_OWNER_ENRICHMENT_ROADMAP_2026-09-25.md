## Purpose

Convert the useful knowledge from three pinned external repositories and three
operator-relayed handoffs into one CVF-native owner-enrichment sequence. CVF
doctrine, operating model, existing contracts, runtime owners, and Local review
remain authoritative. External repositories and handoffs supply patterns,
negative cases, and design questions; they do not redefine CVF identity or
create acceptance authority.

The roadmap composes the inputs instead of opening six unrelated capability
stacks:

```text
Jev judgment evidence
  -> WikiSkill proposal / strict-improvement / rollback evidence
  -> HyperFrames artifact graph / scoped execution / assembly verification
  -> durable execution state and conversation-facing projection
  -> independent verification
  -> meaningful human acceptance when consequence requires it
  -> CVF-owned promotion, closure, or rejection

CVF positioning constraints govern every transition above.
```

## Authorization / Decision

The operator authorized Local to use useful external knowledge while keeping
CVF as the governing root, combine the three previously absorbed repositories
with the three additional handoffs, and build an absorption roadmap.

Local decision:

- retain the completed Jev, WikiSkill, and HyperFrames P0 adaptations as the
  implementation baseline rather than recreating them;
- adapt human-agent boundary value into existing control, closeability, and
  review-capacity owners;
- treat positioning value as a cross-roadmap identity-preservation filter and
  enrich an existing owner only where exact negative search proves a gap;
- evaluate async-runtime value against current MAO and governed-command
  launcher owners before changing code;
- combine accepted deltas in a provider-free offline composition proof;
- reject direct upstream import, new competing architecture, provider/model
  dependence, automatic mutation authority, and completion claims based only
  on notification or agent confidence.

Decision owner: Local CVF reviewer/closer. External web agents remain advisory
research and pattern-mapping roles. A shared-workspace worker is an
`INTERNAL_AGENT` regardless of provider or model.

## Design Control Gate

Every tranche must satisfy all of these invariants:

1. **CVF-first authority.** Existing CVF doctrine and owners decide meaning,
   authority, admission, evidence, and acceptance.
2. **Absorb knowledge, not identity.** Source names and implementation shapes
   may explain provenance but must not become CVF architecture vocabulary by
   default.
3. **Evidence is not authority.** Confidence, probability, agent success,
   child notification, or runtime completion may support routing but cannot
   authorize side effects, promotion, acceptance, or closure.
4. **Separate responsibilities.** Execution, verification, acceptance, and
   accountability remain distinct even when one operator-facing flow presents
   them together.
5. **Meaningful checkpoint.** A human checkpoint is valid only when the human
   receives usable evidence, has a real opportunity and authority to reject,
   and is not asked to replace missing machine verification.
6. **Durability before effect.** Where the owner claims recoverable execution,
   durable intent/admission identity must be committed before the external
   effect boundary and recovery must fail closed on identity ambiguity.
7. **Projection is not truth.** Conversation, UI, workspace, or child-status
   projections are rebuildable views; the owner-designated ledger/receipt or
   verified artifact remains authoritative.
8. **Verification capacity is bounded.** Increased generation or concurrency
   may change batching, not declared scope, required evidence, reviewer
   independence, or acceptance thresholds.
9. **Accepted outcome over activity.** Optimize for a verified accepted
   outcome and bounded review cost, not token minimization, autonomy level,
   number of generated artifacts, or number of cited passing checks.
10. **No duplicate owner.** A new owner surface is forbidden while an existing
    owner can be enriched without violating its authority boundary.

### AKOE-P1 - Human Control And Positioning Reconciliation

P1 must first perform exact negative search and owner comparison. It may then
make only the smallest necessary changes to existing owners.

Required questions:

- Does the current MAO/handoff/closeability contract distinguish execution,
  verification, acceptance, and accountability as separate authorities?
- Does a human checkpoint carry evidence availability, decision opportunity,
  rejection authority, and machine-verification prerequisites, or only an
  approval token?
- Does review admission expose a capacity/saturation condition when generation
  or fan-out exceeds independent verification capacity?
- Is the positioning rule "accepted outcome over activity/autonomy/token
  minimum" already sufficiently owned by doctrine, operating model, and review
  cost controls?
- Does external absorption already reject source identity/architecture import
  while preserving concrete source value?

P1 must not modify frozen doctrine merely to restate the positioning handoff.
A `CONFIRMED_EXISTING` result with locator evidence is a successful absorption
disposition, not a failure to implement.

### AKOE-P2 - Durable Intent And Projection Reconciliation

P2 compares two current CVF execution paths before any implementation change:

- MAO persists delegation reservation and `TASK_ADMITTED` before
  `adapter.invoke()` and treats the event ledger as execution truth;
- the governed-command launcher persists a create-exclusive execution intent
  before runner invocation.

The audit must determine whether the MAO admission record contains sufficient
identity and recovery information for the exact claimed effect boundary, and
whether `INVOCATION_STARTED` timing creates any unowned crash window. A finding
must be demonstrated by a deterministic negative case; document similarity is
not enough.

Required test classes for an accepted delta:

- crash after durable admission but before adapter/effect dispatch;
- crash after effect acceptance but before terminal checkpoint;
- duplicate launch/replay with the same and conflicting identities;
- cancel/completion race;
- stale or contradictory conversation-facing projection;
- recovery after authority, scope, or budget identity mismatch;
- semantic completion withheld despite runtime completion when artifact or
  independent verification evidence is missing.

If source-specific Unreal behavior matters, P2 may propose a separate pinned
source-mirror intake for `unreallabsai/unreal-agent@1b9f778`. Until that intake
is locally verified, the handoff cannot support upstream factual claims.

### AKOE-P3 - Provider-Free Integrated Application Proof

P3 uses a synthetic, reversible use case rather than invoking Jev, WikiSkill,
HyperFrames, Unreal Agent, or a model provider. The scenario must exercise:

1. a bounded judgment with state hash, candidate completeness, no-match escape,
   and evidence-only confidence;
2. one atomic candidate change with incumbent comparison and strict-improvement
   decision;
3. a durable, scoped artifact graph with capped scheduling that preserves the
   full declared scope;
4. execution-state persistence and a non-authoritative conversational/operator
   projection;
5. independent artifact and assembly verification;
6. evidence-backed human acceptance only where the risk route requires it;
7. rejection and rollback that preserve raw evidence and learned knowledge;
8. terminal receipts that distinguish execution success, verification result,
   acceptance decision, and accountable owner.

This is offline integration evidence, not production use proof. Any real
provider or runtime proof remains a fresh operator checkpoint under the live
governance standard.

  Local review;

  treated as acceptance authority;

  disposition;
- common closure records the applicable external-absorption maturity and
  completion token truthfully for each relevant lane; offline tests alone
