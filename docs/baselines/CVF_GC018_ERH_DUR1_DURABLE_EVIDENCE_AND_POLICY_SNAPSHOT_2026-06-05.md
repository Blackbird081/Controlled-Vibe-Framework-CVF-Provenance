## Purpose

Authorize ERH-DUR1 as the next external-review hardening tranche after SAF2.

SAF3 is not opened because SAF2 closed the remaining source-visible safety
gaps in the current ERH safety scope. DUR1 targets two section 4.4 architecture
weaknesses that now have enough runtime foundation to harden as a workflow
chain:

1. Control-plane audit evidence defaults to a JSON store under the operating
   system temp directory. That is better than in-memory storage, but still
   weak for an evidence-governance claim.
2. `policySnapshotId` is generated by a process-local counter and does not map
   to a persisted, reconstructable policy snapshot record.

## Decision / Baseline

Decision: authorize Claude to implement DUR1 under `WORKER_MUST_NOT_COMMIT`.

Baseline facts:

- `control-plane-events.ts` already provides a file-backed control-plane event
  store, append queue, corruption repair, admin read path, and CSV export.
- Its default path is `path.join(os.tmpdir(), '.cvf-data',
  'control-plane-events.json')`, with `CVF_CONTROL_PLANE_EVENTS_PATH` override.
- `web-governance-envelope.ts` already attaches `policySnapshotId` to envelopes
  and receipts.
- `policySnapshotId` currently comes from `_policyCounter` and
  `generatePolicySnapshotId()`, not a persisted snapshot record.
- `/api/execute` already emits audit events through `appendAuditEvent()` and
  returns receipts containing `policySnapshotId`.
- Current line counts: `control-plane-events.ts` 315 lines,
  `web-governance-envelope.ts` 256 lines, `/api/execute/route.ts` 874 lines.
