## Selected Integrated Design

Local selects the existing export -> Web proxy -> engine topology. Keep two authentication boundaries explicit; do not bypass the proxy using the browser session or silently harden every generic API. Add a narrowly scoped bound receipt endpoint in each existing API owner. Generic legacy APIs stay outside this proof. The dedicated Web/engine handlers must not invoke generic fallback paths. No new SDK, host, worker runtime, generic dispatcher, competing ledger or package dependency is selected.

A new real-effect schema/namespace is required because v1 fixes INJECTED_SYNTHETIC_RECEIPT, synthetic IDs, disclosure and DECLARED_UNATTESTED. Preserve v1 byte/semantic compatibility as a fixture lane. New effect keys keep HQ1 fixed-order owner/source/request/effect identity, exclude config/job/version/HTML, and include a distinct effect discriminator. Existing opaque authorities and monotonic intent/start/outcome semantics remain the store owner; extending parser dispatch must never turn v1 grants into new-effect authority. No automatic migration, key reset or old receipt/new HTML reuse.

The first future source assignment is OFFLINE only: implement the complete bound path and its cross-language contract under explicitly injected fixture transports and disposable stores; runtime activation stays fail-closed. Do not release an isolated HTTP wrapper that leaves identity, policy, disclosure or writer contracts for another implicit repair.

## Bound Endpoint And Auth Contract

D01. Server-approved deployment manifest pins Web origin, dedicated proxy path, engine origin/path, instance boot identity, backend kind, store identity, policy/transform/schema revisions, signing-key reference and scope, maximum body/response bytes, timeout and effect class. Digest exact canonical bytes. No URL, store, owner, auth or permit from client headers/body. Runtime values are currently UNKNOWN and are not read in this design. No implicit localhost/default-port admission.

D02. Reuse existing HMAC algorithm as a source pattern, with dedicated credential references/scopes for Web->proxy and proxy->engine. Sign method, canonical path, timestamp, nonce, manifest/config digest and exact raw-body digest. Validate length/time/replay and signature before normalization or ledger effect; identity comes from normal authenticated user/org/team at export. Token equality alone is insufficient for the bound endpoint. Reject invalid credential without session fallback. No credential values in evidence or client response.

D03. Challenge response authenticates challenge nonce, instance identity, config/policy digest, measured backend/store binding and expiry. Evaluation response independently authenticates the same join plus operation/attempt/artifact/payload/owner and committed ledger reference. Recheck at evaluation time; preflight success alone cannot survive store/config/key replacement. Redirects and unknown origin/path deny.

D04. This is authenticated deployment binding, not hardware attestation or a claim that a compromised server tells the truth. Local launch evidence must join the approved isolated root/backend to the actual opened ledger object and process before any effect is admitted. A path string, health version, arbitrary echoed storeId or signed caller-supplied label is insufficient. Restart/replacement changes instance/config identity and fences existing operations; no automatic reuse/retry. Exact mechanism and serialization fixtures must be frozen in the implementation packet, with mismatch/TOCTOU tests. No new engine endpoint is claimed to exist now.

## Data Store Cost And Stop Contract

D08. Proposed first development input is invented ncr-synthetic data, no user corpus or copied active ledger. Both local operation root and engine ledger are fresh disposable roots named by the future work order. Fresh SQLite uses the existing owner without JSON import/cutover; Profile A active JSON remains untouched. This is a proposed development configuration, not selection of production storage. Writer is one owned engine process; capture actual root, process, access/custody and retention before a run. Recovery/backup/RPO/RTO on active data stay a later R4 scope.

D09. Keep256 operations/owner,16KiB lifecycle record cap and no expiry/GC/replay from v1 development bounds; a different real retention policy needs explicit design and authorized redaction preserving deduplication. Store capacity/full/corrupt/unconfirmed denies before send. Test monotonic records and real contention under the future admitted offline envelope, not active data. Do not add rollback/locking/security operations casually; apply local transaction proof standard if the selected implementation introduces those mechanisms.

D10. Proposed transport pilot allows at most one effect-bearing evaluation per logical operation, zero retries, finite total attempts set before launch, and explicit bounded preflight traffic. A call limit is not a hard USD cap. Provider selection/model/pricing/billing are unselected; UNKNOWN cost blocks any paid effect. A provider-free engine transport/ledger exercise can establish only transport/store joins, not live governance proof. W06/provider authority is separate.

D11. Stop fences local publication and aborts local waits; it cannot promise remote cancellation, deleted ledger records or zero billing. Timeout/abort/lost acknowledgement consume the operation, store UNKNOWN and never auto-retry. Existing ledger-window B may report presence only. Recovery may show immutable same-operation reference, not upgrade UNKNOWN or authorize another send. Disable/revoke persists, absence denies, all production modes remain DENY. No timer/watch/daemon/dispatcher is created.
